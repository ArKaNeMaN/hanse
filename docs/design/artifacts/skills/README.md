# Managed skills QA artifacts

Generated by `node docs/design/skills-qa.mjs` for the skill bundles and workspace stage. The harness
starts a throwaway coordinator fixture (`docs/design/skills-qa-server.mts`) with the repository's
local `tsx`, creates a temporary SQLite database and workspace, and drives the real HTTP UI with
Playwright. Nothing here comes from a deployment host, a real project, or a real session.

The fixture seeds synthetic data only:

- Global: `release-checklist` (metadata, license, compatibility, two references, tables/code/links,
  and raw HTML probes), `ops-guide`, `deploy-notes`, `shared-rules`, `triage-bugs`, and `repair-me`
  with corrupt stored metadata (`Invalid here`).
- Project `Atlas`: `project-notes` and a `triage-bugs` tombstone (`Disabled here`).
- Application `web`: `app-playbook`, `shared-rules` with corrupt metadata (`Invalid local
  override`), and `app-broken` with corrupt metadata (`Invalid here`).
- One synthetic human operator token.

The fixture DB is deleted after the run. Screenshots and `report.json` are rewritten on every run;
stale PNGs from older UI versions are removed first.

## Gate

The last deterministic run (2026-10-23) reported **PASS: 12 scenarios, 505 assertions, 29
screenshots, 0 failed assertions, 0 unexpected console/page errors**. Four expected non-2xx console
resource logs (one JSON 400, one server 422, two 409 responses) are recorded in
`report.json.consoleErrors` with `expected: true`; any other console or page error fails the gate.
The harness exits 1 on a failed assertion, a missing/empty screenshot, an unexpected console error,
or a page error.

Run it from any checkout:

```bash
node docs/design/skills-qa.mjs
```

Playwright and Chromium are resolved like `docs/design/capture.mjs`; they are not product
dependencies.
