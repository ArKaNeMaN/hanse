# Chat UX QA artifacts

Generated by `node docs/design/chat-qa.mjs` (plan 0005 phase 6, plan 0008 phase 7, and the context
usage/compaction QA pass). The harness resolves the optional
local Playwright/Chromium install exactly like `docs/design/capture.mjs`; Playwright is not a product
dependency. Missing Playwright or a missing `dist/` build is a blocked gate, not a skip.

The deterministic run self-starts a throwaway `node dist/index.js serve` on a free localhost port with
a temporary workspace/state, intercepts every `/api/apps/**` call with `page.route`, and injects a
fake `EventSource`. It exits 1 on the first failed assertion, console error, or page error. The same
command can target an existing server:

```bash
CHAT_QA_URL=http://127.0.0.1:8792 CHAT_QA_TOKEN=qa-token node docs/design/chat-qa.mjs
```

`report.json` records every scenario, assertion, observation, screenshot path, and the console/page
error list for the deterministic gate. The last deterministic run reported **22 scenarios, 429
assertions, 45 screenshots, zero console/page errors**. The two `read` captures are intentionally not
committed because they contained reference-deployment source data; the `read` assertions remain in
`report.json`. Live-run reports, screenshots, and session identifiers are never committed.

The slash-command scenarios add a `commands` fixture to `installRoutes`: a `GET /commands` list with
the six Hanse entries, application commands (including one MCP prompt and one `shell:"present"` and
one `shell:"unknown"` entry), a disabled row, and a `command_shadowed` warning for the `ide` alias,
plus a `POST .../sessions/:sid/commands` state machine and a `commandGets` cache counter. The
scenarios add these names to `report.json`: `commands-palette` (open via `/` and the Commands
button, filter, result/empty announcements, combobox/listbox ARIA, disabled-row skip, insert-vs-
submit), `commands-shell-confirm`, `commands-shell-unknown`, `commands-stale-400` (one optimistic
row reused and rekeyed after a single retry), `commands-unknown-literal` (`//foo`, an unknown slash,
and a direct-typed shadow), `commands-master` (`/editor`/`/diff` disabled with the reason), and
`commands-popup` (popup-blocked same-tab fallback). `commands-widths` repeats the open palette at
390/768/1440 in dark and light and asserts no horizontal overflow, the in-flow position above the
composer, and 44 px rows at 390. A deliberate non-2xx response still only filters its own expected
resource log.

The phase-7 diff scenarios inject a `Worker` probe before page load to count worker creation,
`tokenize` posts, responses, and terminations. They reuse the same deterministic route/EventSource
fixtures and add these scenario names to `report.json`: `diffs`, `read`, `diff-error`, `diff-lazy`,
`diff-streaming`, `diff-adversarial`, and `diff-timeout`.

The context scenarios add a default D4 snapshot for `GET .../sessions/:sid/context` and a default
`202 {accepted:true, sessionID}` for `POST .../compact` in `installRoutes`, so every existing chat
scenario keeps receiving a valid snapshot instead of `{}`. They add the scenario names
`context-states` (ready/tokens-only/unknown/ineffective), `context-compact` (confirm -> 202 ->
compacting poll -> `session.compacted` -> refreshed ready, plus a fixed 409), `context-switch-race`
(a delayed session-A snapshot must not overwrite session B), and `context-retry` (a `stream.ready`
context GET returns `503 agent_not_running`, then the 750ms retry renders the chip). A deliberate
non-2xx API response makes Chromium log one resource error; those expected 409/503 logs are filtered,
and any other console/page error still fails the gate.

## Session tree

`CHAT_QA_ONLY=session-tree node docs/design/chat-qa.mjs` runs only the deterministic session-tree
scenario and copies its report to `session-tree-report.json` so the canonical `report.json` remains
the full baseline. It covers initial collapse, expand/collapse with `aria-expanded`, a depth-2
grandchild, orphan/leaf roots, a grandchild deep link, search with forced-open ancestors,
clearing search, the collapsed-parent aggregate wait flag, focus restoration after a refresh, a
parent subtree delete with the post-delete refresh, and 1440/390/320 layouts. The full default run
currently stops at the pre-existing `main` queue-strip assertion (`2 rows` vs `1`), reproduced on
clean HEAD; existing scenarios are unchanged.

## Accepted gaps

- The diff scenarios cover 1440 and 390 plus one light diff capture; `read` covers 1440 and 390 dark
  only. The context scenarios cover 1440 dark for every state, one 390 dark ready capture, and one
  768 light ready capture. The remaining screenshots are dark only; reduced motion and 1024/1920 are
  not part of this automated matrix.
- The 390 capture is scrolled to the bottom, so the table is present in the DOM and measured but not
  visible in the frame.
- The deterministic fixtures cover the R1/R15/R16/R17 browser rows (streaming, queue/send, inline
  questions, OMO, tools, tables, width). The full reconnect/hydration/unknown-acceptance matrix and
  the remaining R3/R5/R7/R8/R13/R14 rows have unit/HTTP coverage; they are not all separate browser
  captures here.
- A live smoke was run against a reference deployment. Its report, session identifiers, and
  screenshot are intentionally not committed; only the deterministic harness and sanitized artifacts
  are tracked. The `--live` mode remains available for local verification, but its artifacts must not
  be committed. The full design §14.4 eight-scenario matrix is covered by deterministic
  browser/unit/HTTP tests; a missing live prerequisite fails the gate rather than skipping it.
