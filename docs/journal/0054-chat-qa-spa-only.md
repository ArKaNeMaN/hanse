# 0054 - Chat QA harness is SPA-only

## Context

The deterministic chat browser QA harness (`docs/design/chat-qa.mjs`) still carried a
`CHAT_QA_MODE` switch that defaulted to `legacy`. The legacy chat UI has been removed from the
product, so that default routed the harness through a client that no longer exists. The
`session-tree` scenario exercised only the legacy client, depended on its retired selectors, and was
stale/broken under the SPA, so it could not be used to validate current behavior.

## What changed

- `docs/design/chat-qa.mjs` is now SPA-only in deterministic mode. `CHAT_QA_MODE` and its `legacy`
  default were removed; `LIVE` (`--live`) remains the external-agent mode.
- `assertSpaRouteSet(CHAT_QA_SPA_ROUTES)` runs whenever the harness is not `LIVE`.
- `report.mode` is `LIVE ? "live" : "spa"` and `report.spaRoutes` is
  `LIVE ? null : CHAT_QA_SPA_ROUTES`.
- The event `emit` helper always normalizes harness sequence numbers (the per-call `normalizeSeq`
  option is gone), and the comment no longer mentions the legacy client.
- The self-started server always receives `env.HANSE_UI_SPA_ROUTES = CHAT_QA_SPA_ROUTES`.
- Deleted the legacy-only `sessionTreeFixture()` and `scenarioSessionTree()` functions and removed
  the `session-tree` registry entry. Shared helpers used by other scenarios were left intact.
- `CHAT_QA_ONLY`, `CHAT_QA_SPA_ROUTES`, `LIVE`, and the scenario filter still work.

## Retained historical evidence

`docs/design/artifacts/chat/session-tree-*.png` and
`docs/design/artifacts/chat/session-tree-report.json` are kept unchanged as historical evidence for
the removed scenario. They are no longer regenerated by the harness.

## Residual risk

- The full deterministic harness still stops at the pre-existing `main` feed/composer width
  assertion (`501` vs `568`); it predates the SPA chat cutover and is unrelated to this cleanup.
  Targeted SPA scenarios (for example `turn-status`) are the usable path, and this change does not
  claim a full-harness pass.
- The removed scenario's coverage is gone; the SPA session rail/tree behavior is covered by the
  product's unit/E2E tests rather than this browser harness.

- `CHAT_QA_ONLY=turn-status node docs/design/chat-qa.mjs` - PASS: 1 scenario, 23 assertions, 1

- `npm run check:sensitive` - pass.
- Grep: no `CHAT_QA_MODE`, `sessionTreeFixture`, `scenarioSessionTree`, or `"session-tree"` remains
