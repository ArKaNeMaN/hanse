# Journal - core coordinator

## Stage 1 - State store, registry, CLI (done)

- Scope: persistence + discovery + CLI. Non-goals: spawning, queue, MCP, HTTP.
- Delivered:
  - `src/store/` - SQLite driver (`better-sqlite3`), pragmas (WAL, `synchronous=NORMAL`,
    `busy_timeout=5000`, `foreign_keys=ON`), forward-only migrations (`schema_migrations` with
    checksum), full schema per design §6.
  - `src/registry/` - `discoverProject` (walk up, validate) and idempotent `registerProject`.
  - `src/runtime/` - state-home and path resolution under `XDG_STATE_HOME`.
  - CLI: `hanse init [dir]`, `hanse status [dir]`.
- Decisions:
  - Driver `better-sqlite3` (rejected `node:sqlite`: experimental, needs Node 22.5+).
  - One global coordinator DB at `$XDG_STATE_HOME/hanse/coordinator.db`; per-instance dirs keyed by
    project id.
  - Application id = `<projectId>:<appKey>`; `appKey` = `basename(path)` until the app's own
    `.hanse/app.yaml` is read (Stage 2+).
  - `src/registry/` supersedes `src/coordinator/registry.ts` (removed).
- Verification: `lint`, `typecheck`, `build` clean; 28 tests pass (store, registry, commands, schema,
  config, instance, cli). Smoke: `init` scaffolds the manifest; `status` registers the project and
  creates the DB.
- Deviation: **Stage 0.5 (vertical spike) deferred.** It needs a live authenticated `opencode` and
  affects Stage 5 (delivery), not Stage 1. Recorded as an open item to run before Stage 5.
- Artifacts: `src/store/*`, `src/registry/index.ts`, `src/runtime/*`, `src/cli/*`, tests.
- Next: Stage 0.5 spike, then Stage 2 (launcher).

## Stage 3 - Queue, handoff, writer lock (done)

- Delivered: durable handoff state machine in `src/coordinator/handoff.ts` (9 states, validated
  transitions, idempotent create on the idempotency key, `expireDueHandoffs`), and a cross-process
  writer lock in `src/coordinator/lock.ts` (`FileWriterLock`: `O_EXCL` lock file + pid liveness +
  reclaim of dead holders). Removed the in-memory `src/coordinator/queue.ts` (superseded).
- Decisions: Node exposes no kernel `flock`, so the lock is `O_EXCL` + pid liveness (single node);
  `dispatching` increments `attempts`; a lane is not held while awaiting a sibling (no cross-handoff
  deadlock by construction in this stage).
- Verification: lint/typecheck/build clean; 37 tests pass, including a genuine two-process lock test
  (child holds the lock; parent is blocked; after the child exits the parent acquires it).
- Next: Stage 4 (identity/authn).

## Stage 0.5 - Vertical spike (done)

- Ran `opencode serve` (v1.18.35) with isolated `XDG_*` + `OPENCODE_DB`. Confirmed:
  - the server starts, writes state under the isolated data dir, and exposes an OpenAPI doc (162
    paths) at `/doc`; `/project/current`, `/session`, `/config` respond;
  - the server is **unsecured** unless `OPENCODE_SERVER_PASSWORD` is set - the coordinator must set
    per-instance auth;
  - **steer is available**: `POST /session/{id}/message` (and `prompt_async`), plus an event stream
    (`/event`, `/global/event`). This confirms the delivery model: inject into the target operator
    session and subscribe to events for liveness.
- Not exercised: an actual prompt (avoids model cost); the endpoint surface is confirmed, runtime
  delivery wiring remains the next step.
